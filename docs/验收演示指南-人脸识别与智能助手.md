## 0. 验收要求对照总表

| 任务卡要求 | 实现位置 | 演示动作 | 证据 |
| --- | --- | --- | --- |
| 针对系统/平台构建人脸识别登入模块 | 登录页「人脸登录」页签 | 退出后用人脸登录 | 成功进入首页 + `sys_logininfor` 有“人脸登录成功” |
| 不同用户的注册、特征抽取与存储（向量化数据库） | 个人中心 → 人脸登录；Qdrant 人脸集合或 MySQL 加密模板 | 录入 → 状态显示样本/模板数 | `GET /system/user/face/status` 返回 `enrolled:true`、`samples`、`templateCount` |
| 整合到现有系统的人脸识别登录 | `/faceLogin` 与密码登录同款 JWT | 人脸登录后访问任意菜单 | 登录后功能与密码登录一致 |
| 用户或管理员对信息/图像进行更新与管理 | 个人中心（更新/追加角度/解绑）；用户管理 → 更多 → 人脸登录管理；系统管理 → 人脸管理 | 管理员停用某账号人脸 | 该账号人脸登录被拒，密码仍可登 |
| 人脸图像隐私保护与隔离 | 浏览器端检测+活体+特征，服务端只存 AES-256-GCM 加密模板 | 讲解 + 打开浏览器网络面板看请求体 | 请求体只有 `{username, descriptor[128]}`，无图片 |
| 其他个性化功能 | 多角度模板、需重录标记、失败限流、审计 | 追加角度 / 触发一次失败提示 | 管理页显示模板数；失败提示统一、不泄露账号存在性 |
| 基于 RAG + 大模型构建智能对话 | 智能助手 → 智能问答（仅文档 RAG 模式） | 问文档题 → 看引用 | 轨迹六阶段 + 引用可点开原文 |
| 本地小模型或 API 接入大模型 | Ollama `qwen2.5:7b` / DeepSeek、GLM 可配 | 状态徽标与轨迹里的“本地模型生成” | `GET /mes/ai/status` 的 `localModel` / `externalApi` |
| 不同用户或原始系统资料相互隔离的本地隐私知识库 | 部门库（按 `dept_id` 隔离），接口拒绝跨部门查询 | 用不同部门账号看可见库 | 只能看到本部门库；跨部门参数被拒 |
| 上传、下载、更新或删除（多类型） | 知识库管理：上传、下载原件、重试、删除、版本切换 | 现场上传一份 docx 并删除 | 文档列表状态变化；原件可下载 |
| 文档到向量库的转换、实时嵌入与更新 | 解析 → 分块 → `bge-m3` 嵌入 → Qdrant 集合 `mes_kb_bge_m3_v1` | 上传后在列表看“向量化”状态 | `embedStatus=completed`；问答能命中新文档 |
| 结合 RAG 搭建私有化智能对话、问答界面 | 智能问答页（SSE 流式 + 引用面板） | 连续两问，看流式与引用 | 回答逐字生成、引用可打开 |
| 探索工作流与编排（Dify，做得好加分） | Dify 1.9.0 + 14 节点工作流 | 打开画布，再到运行日志找同一轮 | 同一 `workflow_run_id` 在 MES 轨迹与 Dify 日志都能对上 |
| 基于 GraphRAG 构建智能对话 | 图谱 GraphRAG 模式 | 问实体关系题 | `图谱检索 · 关联 N 个实体、M 条关系` |
| 私密库文档到图数据库的转换、实时更新 | 上传时勾选“纳入知识图谱”，后台异步抽取 | 上传后看“已建图”，再刷新图谱页 | 新实体出现在图谱；失败可“重试建图” |
| 提供 RAG 与 GraphRAG 可选界面，提示词有效融合 | 模式下拉（仅文档 RAG / 图谱 GraphRAG / 自动路由）；图谱分支把实体关系拼进生成提示词 | 同一问题切换两种模式对比 | 两种模式的轨迹分支与回答依据不同 |
| 结合 Neo4j 嵌入前端，知识图谱可视化（节点与关系） | 智能助手 → 知识图谱 | 搜索实体、点节点看关系、看跳数 | 画布显示节点/关系、关系类型与来源 |
| 结合 GraphRAG 搭建问答界面 | 同 GraphRAG 模式 + 引用 | 图谱题回答带引用编号 | 回答里 `[1][2]` 与引用列表对应 |

## 3. 任务-1：人脸识别登入（约 4 分钟）

### 3.1 录入（每人一次）

1. `admin/admin123` + 数学验证码 登录。
2. 右上角头像 → **个人中心** → 页签 **人脸登录**。
3. 状态应为“尚未录入人脸” → 点 **录入人脸**。
4. 弹窗：输入**当前登录密码** → 勾选“我已阅读并同意上述说明，自愿录入人脸特征” → **开始采集**。
5. 浏览器允许摄像头；采集窗口自动开始（只有“取消 / 重新识别”）。
6. 按提示：正对镜头 → `请把脸缓缓转向左侧` → 回正 → `再请把脸转向右侧` → 回正 → `正在采集特征 1/3 … 3/3` → `识别成功`。
7. 关闭弹窗，页面显示 **已录入人脸**、样本帧数、模板数。

### 3.2 登录演示

1. 右上角 → **退出登录**。
2. 登录页顶部三页签：**密码登录 / 验证码登录 / 人脸登录** → 点 **人脸登录**。
3. 只输账号 `admin` → **开始人脸识别** → 重复动作。
4. 成功后直接进首页，权限与密码登录完全一致。

### 3.3 管理与个性化（体现“更新与管理”）

| 动作 | 位置 | 现场说法 |
| --- | --- | --- |
| 更新人脸 / 追加角度 | 个人中心 → 更新人脸 / 追加角度（最多 3 个角度） | 侧脸、戴眼镜时提高通过率，比对取最近角度 |
| 解绑 | 个人中心 → 解绑人脸（需密码） | 特征立即删除 |
| 管理员停用/重置 | 用户管理 → 更多 → **人脸登录管理**；系统管理 → **人脸管理** | 可停用某账号人脸、重置模板、看“需重录” |
| 限流 | 连续 5 次失败 | 10 分钟内拒绝人脸登录，**密码仍可用** |
| 审计 | 系统管理 → 登录日志 | 成功/失败都有记录，失败原因只在服务端 |

### 3.4 隐私与隔离（讲解词）

> “检测、活体、特征提取全在浏览器；服务端只收到 128 个数字，模板用 AES-256-GCM 加密，密钥在部署环境里，数据库里看不到原图。录入和解绑都要再输一次密码，防止会话被盗后改绑。”

可现场佐证：F12 → Network → `/faceLogin` 请求体只有 `{username, descriptor}`，**没有图片或视频**。

### 3.5 常见问题

| 现象 | 处理 |
| --- | --- |
| “人脸录入暂不可用” | 后端没带 `MES_FACE_TEMPLATE_KEY`，按附录 A 重启 |
| “摄像头只能在 HTTPS 或 localhost 下使用” | 用 `http://localhost:8095` 访问，别用 IP |
| 一直“请正对镜头” | 光线太暗/脸太小/戴帽子；靠近并补光 |
| 比对总失败 | 个人中心“更新人脸”重录；或追加重录角度 |

## 4. 任务-2：RAG 私有知识库与智能对话（约 5 分钟）

### 4.1 知识库基本操作（多类型 + 实时嵌入）

入口：智能助手 → **知识库管理**，顶部选 `MES Demo Library`。

1. 点 **上传文档**，选一份 `docx`（也支持 `txt / csv / xlsx / pdf`），填名称、分类、版本号，勾选是否纳入图谱，确认导入。
2. 列表里看状态流转：**解析**（`parseStatus`）→ **向量化**（`embedStatus`）→ 就绪；解析失败可“重试”，建图失败可“重试建图”。
3. 点 **下载原件** 取回原始文件；点 **删除** 移除文档；同一文档可上传新版本并在版本间切换。
4. 讲隔离：库绑定部门，接口拒绝跨部门查询（`只能查看当前账号所属部门的知识库`），因此不同部门互相看不到资料。

**现场加分动作**：上传后立刻提问一个只有新文档才有的细节 → 能命中，说明“实时嵌入与更新”不是离线预处理。

### 4.2 RAG 问答

1. 回到 **智能问答**，模式选 **仅文档 RAG**，资料范围显示 `MES Demo Library`。
2. 问：`红外传感器模块来料检验有哪些要求？`
3. 展开气泡上方 `N 步` → 轨迹应含：`Dify · 问题改写（分支 文档）→ 向量与关键词检索（命中 4 个片段）→ Dify · 文档检索 → 证据排序 → 回答生成 → 引用整理 → 完成回执 → Dify 编排 · 运行 <id>`。
4. 点引用 → 打开原文并定位段落/页码。

讲解点：回答是**流式**的；引用来自授权部门库；排序策略写在轨迹里（“关键词与向量融合排序”）。

### 4.3 大模型接入（本地或 API）

状态徽标悬停或用 `/mes/ai/status` 展示：

- `localModel: online`：本机 Ollama `qwen2.5:7b-instruct`；
- `externalApi`：配了 DeepSeek / GLM 密钥则为 `configured`，未配为 `not_configured`；
- 生成顺序：本地模型 → 已授权外部 API → 仅检索。

### 4.4 Dify 工作流（加分项，约 2 分钟）

1. 打开 <http://127.0.0.1:8082>，进入「MES 智能问答编排」画布，指 14 个节点的链：
   `领取任务 → 问题改写 → 选择检索分支 →（文档/图谱/业务/混合）→ 汇集凭证 → 证据排序 → 回答生成 → 引用整理 → 完成回执`。
2. 点左侧 **日志与标注**，找刚才那一轮（状态成功），与 MES 轨迹末条的运行编号对照。
3. 点任一 HTTP 节点 → **数据处理**：请求体只有 `POST /mes/ai/dify/callback … {"stage":"…","ticket":"…"}`。
4. 结论话术：*“Dify 只做编排和分支判断，问题原文、文档片段、业务数据都在 MES——这就是私有化与数据边界。”*

### 4.5 常见问题

| 现象 | 处理 |
| --- | --- |
| 文档题没有引用 | 文档是否“就绪”；换个含文档关键词的问法 |
| 回答是原文片段 | 本地模型没起或超时；`ollama serve` 后重问 |
| 轨迹没有 Dify 条目 | 徽标是否在线；`docker compose up -d` 后重问 |
| 上传报“请选择有效的文档分类” | 分类只能选：检验规范 / BOM 说明 / 工艺说明 / 操作手册 / 其他 |

## 5. 任务-3：GraphRAG 与知识图谱可视化（约 4 分钟）

### 5.1 建图（文档 → 图数据库）

1. 知识库管理 → 上传文档时勾选 **纳入知识图谱**（注意：开关只在**新建文档**时生效；已存在文档加新版本不会自动建图）。
2. 列表 `graphStatus`：`running → completed`；失败可点 **重试建图**。
3. 抽取内容：`Document / Item / Product / Process / InspectionItem / Defect` 等实体，关系类型含 `USED_IN / HAS_PROCESS / CHECKED_BY / REQUIRES / MAY_CAUSE`。

### 5.2 图谱可视化（Neo4j + 前端）

入口：智能助手 → **知识图谱**。

| 操作 | 看到什么 |
| --- | --- |
| 搜索“红外传感器模块”或 `TG-EL-002` | 命中实体并高亮 |
| 实体类型筛选（Item/Product/Process…） | 只保留对应类型 |
| 关系类型筛选（`USED_IN` 等） | 只看所需关系 |
| 邻居跳数 1 / 2 | 展开一层或两层邻域 |
| 点节点 | 右侧面板显示实体详情、关联关系与来源文档片段 |
| 聚焦 / 取消聚焦 | 以某实体为中心的局部子图 |

讲解：*“图数据在 Neo4j，前端通过 MES 的图谱接口取子图；每条关系都带来源分块，能点回原文。”*

### 5.3 GraphRAG 问答（含提示词融合）

1. 智能问答 → 模式切 **图谱 GraphRAG**。
2. 问：`红外传感器模块与哪些检验项目有关？`
3. 轨迹：`图谱检索 · 关联 13 个实体、17 条关系 → 向量与关键词检索 → 证据排序（图谱关系与文档证据合并排序）→ …`；回答里带引用编号。
4. 同一问题切回 **仅文档 RAG** 再问一次，对比“分支 文档”与“分支 图谱”的差异。

融合说明：图谱分支会把**实体关系三元组**拼进生成提示词（`实体关系及其文档引用`），与文档片段一起交给模型，这就是“RAG + GraphRAG 提示词融合”。

### 5.4 混合问答（可选加分）

模式 **自动路由**，问：`检验规范怎样要求抽检？工单 MO202610270001 的过程检验结果如何？`

一条气泡里同时出现引用与业务表格；轨迹里 `混合问答·文档检索` 与 `混合问答·业务查询` 在**同一个运行编号**下。

## 附录 D · 术语

| 词 | 含义 |
| --- | --- |
| RAG | 先检索资料再让模型回答，回答附引用 |
| GraphRAG | 从文档抽实体关系进图数据库，问答时把关系作为证据 |
| 阶段凭证 | MES 发给 Dify 的一次性通行证，一步一张，用完失效 |
| 退化 | Dify 不可用时 MES 自己完成本轮，并在轨迹标注实际路径 |
| Recall@5 | 前 5 条检索结果里命中标注分块的比例 |
| 活体 | 左右转头动作核验，防止拿照片糊弄摄像头 |
