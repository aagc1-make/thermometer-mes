# 生产领料一键拣货

**目标：** 在现有 Vue 2 / Element UI 页面完成整单拣货，已知单据信息自动带入，库存不足时不给出虚假的成功结果。

**设计：** 保留现有业务样式。拣货页顶部放置整单操作区，主表展示需领、已拣、待拣及分配状态，批次和库位直接可见。一次服务端事务为全部物料补足拣货明细并转为待领出；实际出库沿用现有执行操作。

**实现约束：** 在当前工作区增量修改，保留已有流水线上下文及其他未提交工作。不改变数据库结构，不提交其他任务文件。不自动过账库存。

- [ ] 服务端新增 `IssueAutoPickService.pick(issueId, operator)`，锁领料单和库存，先计算整单方案再写入；FIFO 自动拆批、保留已有有效明细、尊重指定批次、避免相同库存跨行重复分配。缺料明确列出编码和缺口，整单不写入。重复请求不重复生成。现有单头没有持久化的仓库字段，仓库跟随真实库存分配。
- [ ] 提供带现有领料编辑权限的 `POST /mes/wm/issueheader/{issueId}/auto-pick`。候选库存排除冻结、线边库、禁用库位、过期及明确不合格批次。
- [ ] 前端提供列表及详情一键拣货入口，显示加载状态、防重复点击及结果；保留手工调整入口。选库存时自动按剩余需求填写数量。新增单据默认生成编码、按工单填写名称/需求时间/客户；已有数据不覆盖。
- [ ] 验证 FIFO、拆批、部分已拣、共享库存不足、指定批次、重复请求、不可编辑状态、数量精度及前端失败恢复。运行后端测试、前端测试和生产构建，并在独立浏览器检查实际页面。

**重点检查：** 多物料最后一项缺货时前面不能先写；现存明细占用必须从可用量扣除；接口不得信任客户端的物料和库位；重复点击不能重复拣货；查看已执行单据不能显示可编辑操作。
