# 智能助手 RAG 与 GraphRAG 分步实施计划

以《智能助手 RAG 与 GraphRAG 需求规格说明书 v1.0》第 10 章为顺序，以本机演示为验收环境。每次只实现一个小任务，给出可复核的结果，等用户确认后再进入下一项。

## M1 文档问答基础

1. **建立知识库基础表**。在 `sql/patch_20261114_ai_kb_schema.sql` 中新增部门库、文档、版本、入库任务四张表。在独立 MySQL 8 实例用现有 RuoYi 部门和用户表验证新建、重复执行、归属一致性和版本唯一性。
2. 实现部门库创建及本部门库列表。使用两个部门账号验证列表可见范围及无权限提示。最基本的授权检查随接口落地。
   - PRD Step A 验收覆盖建库错误提示、管理员逐部门查看、软删除后的同名文档、403 审计、状态接口兼容及文档分块表。完成本次验收后再进入上传。
3. 打通 TXT 上传、解析和原件下载。通过知识库管理页上传演示文档，查看解析结果并下载核对原件。
4. 逐步接入 MD、CSV、PDF、DOCX、XLSX 和 HTML 解析。每种格式用独立样本检查正文和引用位置。
5. 接入 CPU 嵌入服务和 Qdrant。上传后能查到相应分块，界面能看到入库进度。
6. 实现基础 RAG 问答及来源引用。在演示环境复用已配置且获准使用的外部 API，用演示资料验证命中、原文定位和依据不足时的提示。
7. 接通本地 GPU 与外部模型通道。分别验证各通道，检查本地优先、授权外部兜底和仅检索降级。

## M2 权限与文档生命周期

8. 逐入口校验部门隔离和审计。用不同部门账号验证文件、引用和检索权限。
9. 实现版本替换和删除。验证新版入库成功后切换引用、失败时保留可用旧版，以及删除后的历史引用标识。
10. 保存问答会话。刷新后可找回本用户的历史会话和引用。

## M3 至 M6 数据问答、图谱与编排

11. 用一个库存只读工具打通模型调用，再按工具逐个扩展。检查参数、部门权限、聚合数值、审计和规则兜底。
12. 选用检验规范做首条 GraphRAG 链路。验证抽取、Neo4j 写入、关系问答和引用，再扩展到 BOM、工艺说明及增量更新。
13. 在助手中显示图谱节点和关系。验证节点检索、邻居展开以及部门可见范围。
14. 接入四档模式及三路融合。分别演示文档、图谱、业务数据和混合问题。
15. 在本机部署 Dify，打通问题改写、检索、重排、生成和引用格式化的问答工作流，再接入 MES 只读工具节点。由 MES 调用工作流，查看画布和节点运行日志，并逐项演示评审确定的三个创新点和降级路径。
16. 用项目自带的演示数据完成本机的教师现场操作彩排，在系统评测页检查端到端回归与性能结果。

## 第一项的验证边界

- 新脚本在现有基础表之后执行，并可重复执行。四张表为空时，既有助手仍可照常使用。
- 一个部门最多一个库。文档的部门必须与所属库一致。同名同分类按库识别，同一文档的版本号唯一且最多一个启用版本。
- 文件上传、查询授权和有状态的版本切换由后续小任务实现。第一项在测试库核对数据库约束和结果，无页面操作。

在已导入 `sql/deploy/01_schema.sql` 的 MySQL 8 测试库中打开 MySQL 客户端，执行：

```sql
SOURCE E:/JavaCode/sql/patch_20261114_ai_kb_schema.sql
SHOW TABLES LIKE 'kb_%';
```

应看到 `kb_library`、`kb_document`、`kb_document_version` 和 `kb_ingest_task`。在同一测试库再次执行脚本，已有表和记录应保留。

## 第二项验收

重新搭建本机演示库时，在导入基础结构和演示数据之后，执行 `backend/ktg-mes/sql/patch_20261101_workorder_sales_linkage.sql`，补齐现有工单流水线查询依赖的销售出库行字段，再执行知识库建表补丁。

1. 在已执行建表补丁的演示环境启动新版 MES。使用系统管理员账号打开「智能助手 → 智能问答 → 知识库 → 创建部门库」。
2. 为两个测试部门各建一个库。若部门重名，核对下拉列表中的部门编号。重复为同一部门建库时，系统应提示该部门已有库。
3. 退出并分别登录两个部门的账号。打开「知识库」，核对「部门知识库」只显示当前账号所属部门的库。普通成员应看不到创建按钮。
4. 用未配置部门库的账号查看空列表。原「浏览器资料」仍可用于既有的文档导入和知识问答，部门库的文档上传从下一项开始接入。

## PRD Step A 验收

1. 对已导入基础数据的测试库再次执行知识库建表补丁，确认新增 `kb_document_chunk`，并验证重跑脚本能保留数据。软删除文档应释放库内同分类的名称，同时保留历史记录。
2. 管理员打开「知识库」，用「查看部门」切换已建库的部门。打开创建弹窗，核对同名部门的上级路径及编号，并核对已建库选项呈禁用状态。
3. 用普通成员登录，核对页面仅显示其所属部门的库。确认越权请求在操作日志中记录账号、路径及查询参数，凭据值显示为遮盖文本。
4. 核对 `/mes/ai/status` 的 GET 和 POST 返回一致。上线文档上传前，确认 50 MB 文件上限、60 MB 请求上限及 `mes.ai.kb.storage-root` 指向私有目录。外部模型当前仅显示配置状态，其余通道显示尚未接入。

## PRD Step B 验收

启动新版后端前，在目标演示库依次执行 `sql/patch_20261114_ai_kb_schema.sql` 和 `sql/patch_20261119_ai_kb_menu.sql`。知识库菜单沿用智能问答的角色授权，已登录账号刷新页面后重新加载菜单。

在「智能助手 → 知识库管理」选择一个部门库，以管理员或库负责人身份上传文档。解析完成后可预览或下载原件。上传新版时，旧版保持可用，直到新版解析成功。删除文档会终止待处理任务、清除分块并关闭原件访问，原件在七天后由后台清理。此阶段的向量化、图谱与检索就绪状态在页面标为待处理。

## PRD Step C 验收

打开「智能问答」，选择「仅文档 RAG」，用本部门已解析的文档提问。回答正文的引用编号会打开右侧原文，执行轨迹会显示本轮实际走过的检索与回答通道。仅检索时，回答直接摘录命中的原文。

本机服务默认使用 Ollama 的 11434 端口和 Qdrant 的 6333 端口。Ollama 中配置 `qwen2.5:7b-instruct-q4_K_M` 和 `bge-m3` 后，已解析文档会自动建立向量索引。模型或服务地址通过 `MES_AI_LOCAL_MODEL`、`MES_AI_EMBEDDING_MODEL`、`MES_AI_OLLAMA_URL` 和 `MES_AI_QDRANT_URL` 调整。更换嵌入模型时使用新的 `MES_AI_QDRANT_COLLECTION`，并重建已有向量索引。

管理员可在引擎状态中模拟本地模型离线。外部 API 使用现有配置，外发本轮问题和命中文档片段前由用户确认。未授权外发或外部服务不可用时，页面显示仅检索回答。

## PRD Step E 实施与验收

部署时执行 `sql/patch_20261119_ai_graph_menu.sql`，并为 MES 配置 `MES_AI_NEO4J_URL`、`MES_AI_NEO4J_DATABASE`、`MES_AI_NEO4J_USER` 和 `MES_AI_NEO4J_PASSWORD`。共享 Neo4j 实例时，为每套 MES 设置独立的 `MES_AI_NEO4J_NAMESPACE`。MES 继续用 Java 8，通过 Neo4j 5.26 的 HTTP Query API 读写图谱。

1. 复用文档的建图开关、有效版本与入库任务。以 MES 编码及无歧义名称绑定实体，记录关系对应的分块，将每个版本的增量写入 Neo4j。读取时同时约束部门库和有效版本。
2. 增加知识图谱菜单、点阵画布和节点详情。搜索实体、切换跳数，展开其关系，查看关联段落。物料节点可直接在智能问答发起库存查询。
3. 图谱模式与自动模式的关系问题先取子图，再与部门文档候选合并。混合问题在同一轮展示文档引用、子图以及只读查询结果。
4. 演示环境上传一份含真实 MES 编码和关系的 BOM 说明，等待抽取完成。从图谱页搜索节点并查看来源，再由节点发起库存查询，核对执行结果。

## PRD Step F 第一步

先接通数据问答。MES 将支持现有规则识别的问题登记为短时任务，Dify 用 HTTP 节点回调执行任务。回调使用原提问账号的权限，业务事实仍由已有的只读工具查询。工作流只接收一次性任务凭证和 HTTP 回执。

以演示库的物料库存问题走通一次 MES → 工作流 → MES 回调 → 用户结果。工作流异常时复用同一次只读查询。文档与图谱的 Dify 编排、评测页面和演示数据放到后续小步。

在自托管 Dify 导入 `docs/dify/mes-readonly-workflow.yml`。把工作流环境变量 `mes_callback_url` 设为 Dify 可以访问的 MES 地址，包含路径 `/mes/ai/dify/callback`。发布工作流，给 MES 配置 `MES_AI_DIFY_URL`（Dify 的 API 基址，末尾为 `/v1`）和该工作流的 `MES_AI_DIFY_KEY`，然后重启 MES。工作流调用与回调需到达同一 MES 实例。线上通信应使用部署的可信内网或 HTTPS。

在「数据问答」输入「查询 TG-EL-002 当前库存」。成功时执行轨迹会记录 Dify 的运行编号，可在对应工作流的日志中查看 HTTP 节点耗时。工作流应只记录任务凭证和回执码，物料编码及库存数量可在 MES 问答页面核对。

## PRD Step F 第二步

部门文档问答和 GraphRAG 使用同一个回调工作流。MES 在签发凭证前校验所选部门库，回调只执行本轮检索及候选合并排序。回答生成、文档引用与子图仍通过 MES 的问答事件流返回。已有工作流使用同一回调协议，可以沿用。

在「图谱 GraphRAG」输入「红外传感器模块用于哪个产品？」，验证回答能展示关联子图、有效的 BOM 文档引用和 Dify 执行轨迹。未配置工作流时直接检索，工作流未完成时复用本轮 MES 检索结果。

## PRD Step F 第三步

执行 `sql/patch_20261120_ai_evaluation_menu.sql` 后，管理员可打开「智能助手 → 问答评测」，选择部门库、运行评测并下载本轮报告。

首版采用现有测温枪演示样例。两题文档检索查看真实前五条候选，库存三题与库存表独立汇总核对，引用覆盖率检查仅检索回答的证据段落，图谱准确率抽检演示 BOM 来源的语义关系。各指标显示实际分子、分母和无法评测的样例。30 道文档题、20 道数据题及 100 条三元组属于后续完整验收集。

## PRD Step F 第四步

在本机 18082 端口的隔离测温枪演示环境运行 `scripts/seed-ai-evaluation-demo.mjs <清单输出路径>`。通过 `MES_DEMO_USER` 与 `MES_DEMO_PASSWORD` 或 `MES_DEMO_TOKEN` 提供演示库管理员授权。脚本读取演示工单和启用的 BOM，通过知识库上传接口在研发、运维和测试库各放入五份资料。相同版本和内容可重复运行。资料解析、建图完成后才写出清单。

为演示后端设置 `MES_AI_EVALUATION_SUITE_FILE` 指向该清单。管理员在「问答评测」选择「三部门验收集」，即可一次运行 30 道文档题、20 道数值题和 100 条图谱关系标注。数值题涵盖库存、工单已生产量和入库流水。报告显示实际计入的分母，以及未抽出关系或缺少基准数据的样例。引用覆盖率仍针对仅检索回答。采用完整验收集的页面不影响各部门库的试跑入口。
