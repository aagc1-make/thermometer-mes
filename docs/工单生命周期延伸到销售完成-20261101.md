# 工单生命周期延伸到销售完成 —— 交付与自检（2026-11-01）

> 需求：流水线再往下延伸到「销售完成」，工单生命周期覆盖到产品销售完成，销售单（销售出库单）要能添加"工单生成的产品"。
> 环境：MySQL 8.0.44（3307，演示库 `j2eedb_it`）、后端 8081（`ktg-admin.jar` 覆盖数据源到 `j2eedb_it`）、前端 `ktg-mes-ui/dist`。
> 本轮全部真实验证只在 `j2eedb_it` 执行；`j2eedb` 只同步执行了表结构补丁，未写入业务数据。

## 一、业务口径

工单主线从 8 步扩展到 **9 步**：

`工单确认 → 生产排产 → 备料检查 → 生产领料 → 生产报工 → 过程检验 → 工单完工 → 产品入库 → 销售完成`

| 口径 | 定义 |
|---|---|
| 销售完成 | 本工单产品**已执行发货**（销售出库单 `FINISHED`）的数量 ≥ 本工单产品**已执行入库**的数量 |
| 可售数量 | 已入库（`FINISHED` 产品入库行）− 已开单（未取消的销售出库行；草稿与在途都占用，防超卖） |
| 不提前完成 | 销售出库草稿 / 待拣货 / 待发运 / 待执行只算"在途"，不把第 9 步点亮 |
| 半成品子工单 | 第 9 步为"不适用"（产出在线边库随整机入库，不单独开销售单） |
| 历史单据 | 无法唯一回溯到工单的出库行保持为空，不猜测；可售清单据此不重复扣减 |

## 三、接口

```
GET /mes/wm/productsales/workorderProducts?pageNum=1&pageSize=10
    &workorderCodeLike=&itemCodeLike=&itemNameLike=&onlyAvailable=Y&excludeLineId=
```

- `onlyAvailable` 默认 `Y`（只列可售 > 0）；传 `N` 可看全部。
- `excludeLineId`：编辑已有出库行时排除自身占用。
- 返回行：`workorderId/workorderCode/workorderName/workorderStatus`、`itemId/itemCode/itemName/specification/unitOfMeasure/unitName`、`batchId/batchCode`、`receivedQuantity/issuedQuantity/availableQuantity`、`recptCode/recptDate`。

销售出库行列表（`/mes/wm/productsalesline/list`）新增 `workorderId`、`workorderCode`，并附带 `salesCode`、`salesStatus`（所属出库单号与状态），供流水线判断"已发货"。

1. 代码回滚到改动前（本条改动涉及列，前端/后端须一起回退，否则查列表会报未知列）。
2. 执行 `backend/ktg-mes/sql/patch_20261101_workorder_sales_linkage_rollback.sql`：
   - 先删索引，再删 `workorder_code`、`workorder_id`；

## 七、已知边界

- **多批次**：同一工单同一产品有多张入库批次时，选择器不猜批次（留空），由拣货按实际库存批次选；数量仍按工单汇总。
- **外购转售**：没有成品入库记录的产品不挂工单，按普通销售出库流程，不影响开单。
- **历史行回填**：仅当「产品 + 批次」在已执行入库记录里唯一对应一张工单才回填；本次演示库回填 5 行，仍有 6 行（旧 `XS…` 单据共用批次 `BAT00000157`、一张隔离库验证单）无法唯一回溯，保持为空，工单流水线不计入它们。
- **销售退货**（`wm_rt_sales`）未回写工单：退货后已发货量不会自动回退，本步骤仍按"累计已执行出库"计算；若需要"退货后回退销售完成"，需在退货执行时扣减，可作为后续增量。
