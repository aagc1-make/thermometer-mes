# 智能助手演示脚本

> 依据当前代码（`ktg-mes-ui/src/views/mes/ai/*`、`backend/.../mes/ai/*`）整理，按“点哪里 → 说什么 → 应看到什么”编写。
> 主流程约 12 分钟，精简版 3 分钟；文末附翻车点与补救。

## 二、主流程（10 步）

### 步骤 1｜引擎状态：先讲清“有哪几条通道”

- **操作**：进「智能助手 → 智能问答」，点右上角引擎状态按钮。
- **应看到**：本地 7B、外部 API、向量库、图谱、Dify 五项状态；管理员可见「模拟本地模型离线」开关。
- **话术**：降级顺序是「本地模型 → 已授权外部 API → 仅检索」，任何一级不可用都不会白屏，且界面会明示当前走的是哪条。

### 步骤 2｜知识库：文档怎么进来、怎么变成可检索

- **操作**：点右上「知识库管理」。
- **应看到**：部门库下拉、「上传文档」、「部门库设置」（管理员）、「浏览图谱」；文档表有「处理进度」列，分**解析 / 向量 / 图谱 / 就绪**四段。
- **操作**：点「上传文档」，走一遍表单：
  - 原件：PDF / DOCX / TXT / MD / CSV / XLSX / HTML，单文件 ≤ 50 MB
  - 文档名称、分类、版本号（如 `V2.0`）
  - **「纳入知识图谱」开关**——这是任务 3 的入口，演示时一定打开
- **应看到**：状态从「解析中」→「向量」→「图谱」→「就绪」，通常几十秒；点「预览」能看到切块后的正文。
- **话术**：同一份文档可以「上传新版」，新版索引成功前旧版保持可用——不会出现“更新到一半搜不到”。

### 步骤 3｜仅文档 RAG：引用可点、可核

- **操作**：回会话页，模式下拉切「**仅文档 RAG**」，输入：`红外传感器来料检验有哪些要求？`
- **应看到**：
  - 回答正文带 `[1] [2]` 引用编号
  - 展开「执行轨迹」，有检索、重排、生成的耗时
  - 点引用 → 右侧抽屉出原文片段与来源文档
- **话术**：每条结论都能点回原文，这是“可核对”，不是“看起来对”。

### 步骤 4｜拒答：证明它不会编

- **操作**：同模式问一个库里没有的问题，例如：`Q/TC 99-2026 检验规范第 8 章怎么写？`
- **应看到**：明确告知资料未收录 / 证据不足，**不给出编造条款**。
- **话术**：宁可拒答也不编，这是助手能不能进生产的分界线。

### 步骤 5｜图谱 GraphRAG：关系问题

- **操作**：模式切「**图谱 GraphRAG**」，输入：`红外传感器模块用于哪个产品？`
- **应看到**：
  - 回答下方出现「**图谱子图 · N 个实体**」按钮
  - 点开 → 右侧抽屉里是节点/关系图 + 命中实体列表
  - 回答同时带文档引用（图给了关系，文档给了依据）
- **话术**：文档被切碎后跨段的关系会丢，图谱就是补这条链路：先实体链接定位节点，再扩 1—2 跳。

### 步骤 6｜知识图谱页：能自己查、自己走

- **操作**：点右上「知识图谱」（或知识库页「浏览图谱」）。
- **应看到并依次演示**：
  1. 顶栏选部门库；搜索框输入 `TG-EL-002` 或 `红外`（支持名称与 MES 编码）
  2. 画布按类型着色：物料/产品/工序/设备/检验项/工单/缺陷/部门/文档，边上有关系标签
  3. 跳数切「1 跳 / 2 跳」，点节点 → 「展开邻居」
  4. 实体类型、关系类型筛选
  5. 右侧详情看属性；有权限时出现「**查实时库存**」——从图直接跳业务查询
- **话术**：这不是静态截图，是可搜索、可展开、能回到业务动作的界面；节点超过上限会提示缩小范围，不会卡死。

### 步骤 7｜数据问答：数字来自数据库，不是模型

- **操作**：模式切「**数据问答**」，依次问（问法已验证会被规则命中）：

| 问法 | 命中能力 |
| --- | --- |
| `TG-EL-002 现在库存多少` | 库存/结存 |
| `现在哪些物料低于安全库存` | 安全库存预警 |
| `这个月入库多少` / `TG-EL-002 出入库流水` | 出入库流水 |
| `我们生产什么产品` / `成品是什么` | 产品目录（整机成品与自制半成品） |
| `哪些工单逾期` / `MO 开头的工单进度` | 工单进度 |
| `最近的 IQC 检验记录` / `不合格率` | 检验记录 |
| `TG-200 的 BOM 有哪些组件` | BOM 展开 |

- **应看到**：表格卡片 + 底部「数据来源」；点「数据来源」看本轮查询了哪几张表。
- **话术**：库存、数量、进度这些数字由后端 SQL 算完再给模型，模型只负责表述——**算数不交给模型**。

### 步骤 8｜自动路由：混合问题一轮答两路

- **操作**：模式切「**自动路由**」，输入：`TG-EL-002 的检验要求是什么，现在还有多少库存？`
- **应看到**：同一轮里既有文档引用，又有数据卡片，执行轨迹标注用了哪几路。
- **话术**：这就是“三路统一路由”——不是两个割裂的助手。

### 步骤 9｜降级：断掉模型也不白屏

- **操作**：管理员在引擎状态里打开「模拟本地模型离线」，重问步骤 3 的问题。
- **应看到**：回答降级为「仅检索」的摘录式回答，并提示当前通道；页面不报错。
- **话术**：可用性优先——模型挂了系统仍然能给出原文级证据。

### 步骤 10｜评测页：用数字收尾

- **操作**：右上「问答评测」（管理员可见），选部门库 → 「运行评测」→ 看指标 → 「下载报告」。
- **应看到**：检索命中、数据题核对、引用覆盖率、图谱关系抽检等指标，且显示实际分子分母。
- **话术**：指标不是我们自己说的，是页面现场跑出来的。

## 三、可选加分项

### A. 全流程贯通（慎用）

- **位置**：会话页右上「全流程贯通」→「开始执行」。
- **效果**：按 BOM 与工艺路线自动建单并推进——采购、入库、工单、生产、检验、销售、结存，最后给出「本轮生产 10 台 / 销售 6 台 / 结存 4 台」的闭环核对。
- **注意**：**会真实生成单据、变更库存**。要么演示前在演示库跑，要么放在最后跑，绝不要在开头跑。

### B. Dify 编排画布

- **位置**：自托管 Dify → 对应工作流。
- **演示**：画布结构（开始 → HTTP 回调 MES → 结束）、运行日志里每个节点的耗时与输入输出；说明 MES 通过 API 触发，Dify 不落业务数据。
- **现状提醒**：目前只有一个“回调式”最小工作流，属于**接口打通**，还没到“多节点编排”。如果时间允许，补一个含条件分支/并行的版本再演示，效果差别很大。

### C. 草稿类写操作（体现“AI 不替人拍板”）

- 输入：`帮我新增一个到货通知，TG-EL-002 到货 100 个` / `创建一个 TG-200 的生产工单，数量 10`
- **应看到**：先出**草稿确认卡片**（物料、数量、供应商/日期可调），点「确认创建」才落库；取消则什么都不发生。
- **话术**：所有写操作都停在“草稿—人工确认”这一步，模型没有直接写库的权限。

## 四、翻车点与补救

| 现象 | 原因 | 补救 |
| --- | --- | --- |
| 数据问答答“没找到物料” | 编码不存在或写错（编码必须命中 `TG-EL-002` 这种带连字符的格式） | 换示例问题按钮里的「实时库存」那条 |
| 图谱页空白 | 未选部门库 / 文档没勾「纳入知识图谱」/ 建图未完成 | 换有图谱状态的库；先在知识库页看「图谱」段是否就绪 |
| 图谱问答没出子图 | 问题里没有可链接的实体 | 用编码或明确物料名提问 |
| 引用点不开 | 文档是旧版本或已删除 | 换一条引用演示 |
| 回答很慢 | 本地 7B 首次加载 | 演示前先随便问一次预热 |
| 全流程贯通报错 | 演示库单据状态冲突 | 尽量在干净演示库跑；报错时用「核对原单据并继续」 |
| 评测页指标缺失 | 未配置演示清单或库不匹配 | 提前跑一次确认，别现场首跑 |

## 五、3 分钟速览版（时间紧时用）

1. 知识库 → 一份文档的「解析/向量/图谱/就绪」四段进度
2. 仅文档 RAG 问 1 个 → 点开引用看原文
3. 图谱 GraphRAG 问 1 个 → 点「图谱子图 · N 个实体」
4. 知识图谱页搜 `TG-EL-002` → 展开邻居 → 点「查实时库存」
5. 数据问答问库存 → 表格 + 数据来源
6. 引擎状态：讲降级顺序

---

## 六、收尾话术（30 秒）

> 这个助手做三件事：**查得到**（文档、图谱、业务数据三路统一路由）、**可核对**（每条结论带引用和来源）、**不越权**（只读工具 + 草稿确认，模型不直接写库）。数字由后端计算，模型只负责表达；模型不可用时降级为仅检索，不整体不可用。
