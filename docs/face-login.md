# 人脸登录（浏览器本地 1:1 比对）

## 结论与定位

在现有账号密码登录之外，增加“账号 + 人脸”的第二条登录路径。它适合演示和内部车间终端：

- 人脸只作为**登录方式之一**，不替代密码；密码登录、验证码登录保持原样。
- 采用 **1:1 比对**（先输入账号，再比对该账号已录入的人脸），不做 1:N 刷脸检索，避免共用终端上误识别到其他人。
- 人脸检测、活体判断、特征提取全部在浏览器完成，服务端只接收 128 维特征并做距离比对，不接触照片和视频。

## 使用

1. 先用密码登录，进入“个人中心 → 人脸登录”。
2. 点“录入人脸”，输入当前登录密码，勾选授权说明，点“开始采集”。
3. 正对摄像头，按提示完成两步动作：**向左转头 → 向右转头**，每次转完回正。动作顺序固定，确认是同一张脸后采集 3 帧。
4. 需要提高侧脸或戴眼镜时的通过率，可在个人中心点“追加角度”，最多再录 3 个角度（主模板不变，比对时取最近的一个）。
5. 退出后回到登录页，切到“人脸登录”，输入账号，点“开始人脸识别”即可登录。
6. 需要停用时，在个人中心点“解绑人脸”，输入密码后特征立即删除。

有用户编辑权限的管理员可在“用户管理 → 更多 → 人脸登录管理”中对单个账号启停或解绑；需要总览时用“系统管理 → 人脸管理”，可看到录入状态、模板数、算法版本（过期的会标红“需重录”），并支持按账号搜索、批量停用与重置。

个人中心打开“人脸登录”页签时会重新读取录入状态和登录可用性。管理员停用人脸登录后，已录入的模板仍可由用户本人解绑。系统级开关关闭或模板存储未就绪时暂停新录入。

超过 5 次比对失败会在 10 分钟内拒绝该账号的人脸登录（可用密码登录），失败次数记录在 Redis，窗口和阈值可配置。

## 数据流

```
浏览器                                   服务端
摄像头 → TinyFaceDetector 检测人脸
      → 68 点关键点：左右转头活体
      → FaceRecognitionNet 128 维特征
      → 多帧平均 → POST /faceLogin
                                    查 sys_user_face → 欧氏距离 ≤ 阈值
                                    → 通过：签发同款 JWT / 失败：统一提示 + 审计
```

- 关键点：`face-api.js 0.22.2`（`public/face-api/face-api.min.js`），模型：`tiny_face_detector`、`face_landmark_68`、`face_recognition`，共约 6.8MB，放在 `public/face-api/models`，首次使用时加载。
- 活体：由正脸帧建立鼻尖位置基准，固定顺序完成「向左转头 → 向右转头」。每步需先回正，转向必须与提示方向一致（鼻尖偏移 ≥ 0.09 倍人脸宽度），转到位后回到正位（偏移 ≤ 0.07）才计为该步完成，每步最多 6 秒。**不要求眨眼**：face-api 的 68 点模型对闭眼状态跟踪很差，EAR 常降不下来，实测误判率太高，因此只保留几何位移稳定、动作又快又好的左右转头。
- 阈值：欧氏距离 `0.55`；同一人通常 0.3~0.5，不同人通常大于 0.6。前端 `FACE_THRESHOLD` 与后端 `mes.face.threshold` 必须一致，单元测试会校验。

## 安全与隐私设计

| 关注点 | 处理 |
|---|---|
| 生物特征存储 | 128 维模板使用与账号绑定的 AES-256-GCM 加密。专用库启用后，Qdrant 按账号编号保存密文和录入元数据，MySQL 保存账号与人脸登录策略。解绑删除当前模板。 |
| 账号枚举 | 未录入、比对失败、账号不存在统一返回“账号未录入人脸或人脸不匹配” |
| 暴力试探 | 账号维度 5 次 / 10 分钟；IP 维度 20 次 / 10 分钟（避免共享出口误伤所有人）。计数在 Redis，登录成功清零；不存在的账号只计入 IP 维度，避免任意用户名撑大缓存 |
| 会话劫持后改绑 | 本人录入或解绑需要重新输入登录密码，并限制密码尝试次数；管理员解绑校验用户编辑权限、数据范围并记入审计 |
| 知情同意 | 录入前必须勾选授权说明，服务端校验 `agree=true` 才写入；写入时记录 `consent_at` 与授权说明版本 `consent_version`，便于举证与撤回 |
| 多角度模板 | 主模板之外可追加最多 3 个角度，均加密存储，比对时取与采集特征最近的一个；算法版本不一致的模板不参与比对，并在管理页标记“需重录” |
| 审计 | 成功/失败均写 `sys_logininfor`，失败原因只记服务端（如 `NOT_MATCHED，distance=4.4879`） |
| 传输 | 只传特征；生产环境必须 HTTPS，否则特征与令牌可被截获 |
| 权限 | `/faceLogin` 匿名但限流；`/system/user/face/**` 需登录，只能操作本人模板 |

**能力边界**。当前活体属于浏览器端动作核验。自拍视频回放、虚拟摄像头和客户端篡改属于独立的安全评估范围，现有采集流程尚未达到生产级防伪认证要求。

## 配置

`backend/ktg-mes/ktg-admin/src/main/resources/application.yml`：

```yaml
mes:
  face:
    enabled: true        # 关闭后登录与录入接口直接拒绝
    encryption-key: ${MES_FACE_TEMPLATE_KEY:}
    qdrant-url: ${MES_FACE_QDRANT_URL:}
    qdrant-key: ${MES_FACE_QDRANT_KEY:}
    qdrant-collection: ${MES_FACE_QDRANT_COLLECTION:mes_face_templates}
    threshold: 0.55      # 欧氏距离阈值，调大更宽松
    max-fail: 5          # 连续失败次数上限
    fail-window: 600     # 失败计数窗口（秒）
```

建表脚本：`sql/face_login.sql`（`sys_user_face`）。

`MES_FACE_TEMPLATE_KEY` 由部署环境提供，值为随机生成的 32 字节密钥的 Base64 表示。同一套数据库的后端实例和后续重启应使用同一把密钥，并由部署环境独立保管。密钥缺失或格式不正确时暂停人脸录入和登录，账号密码登录仍可使用。

配置 `MES_FACE_QDRANT_URL` 和独立的 `MES_FACE_QDRANT_KEY` 后，启动时会初始化人脸专用集合。集合按账号编号保存模板密文及录入状态所需字段，登录比对在应用内存中完成。应用在 Qdrant 确认持久化后清理对应的旧 MySQL 模板，保留录入时间与启停状态。无效模板由用户重新录入。启用专用模板库的部署应持续使用同一套 Qdrant 存储和模板加密密钥。未配置 Qdrant 的部署继续使用 MySQL 加密模板存储。

本机演示使用 `127.0.0.1:16333` 的独立 Qdrant 实例。跨主机部署的模板库地址应使用 HTTPS。

前端资源：`ktg-mes-ui/public/face-api/`；构建后随 `dist/face-api` 发布。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/faceLogin` | 匿名，`{username, descriptor}`，成功返回 `{token}` |
| GET | `/system/user/face/status` | 当前账号是否已录入 |
| POST | `/system/user/face/enroll` | `{password, descriptor, samples, quality, agree}`，录入/更新 |
| DELETE | `/system/user/face` | `{password}`，解绑并删除特征 |
| DELETE | `/system/user/{userId}/face-status` | 管理员解绑指定用户的当前人脸模板 |

## 验证记录（2026-11-01）

- 离线单测：`node scripts/run-unit-tests.mjs`，其中 7 项覆盖特征校验、阈值、多帧平均、鼻尖归一化、左右转头活体的方向与时序、前后端阈值一致性。
- 后端 Java 单测：`FaceTemplateTest` 6 项通过（解析、维度、常量向量、距离、平均）。
- 后端全链路脚本：验证码登录 → 录入 → 状态 → 同特征登录 → 令牌访问 `/getInfo` → 异特征拒绝 → 常量特征拒绝 → 不存在账号统一提示 → 密码错误解绑被拒 → 正确解绑 → 解绑后不可登录 → 连续失败触发限流 → 清理计数，全部通过。
- 浏览器验证（Chrome headless + 真实人像）：登录页人脸 Tab 与按钮可见；摄像头打开、模型加载、假摄像头下给出“没有检测到人脸”提示；取消后释放摄像头；页面内从真实人像提取 128 维特征（score 0.907）；经代理录入成功；人脸登录拿到令牌；调用登录页真实方法后进入 `/index`；个人中心显示“已录入人脸”；验证后清理模板。
- 登录审计可在 `sys_logininfor` 查询到“人脸登录成功/失败”记录。

## 已知限制

- 仅支持具备摄像头且为安全上下文（HTTPS / localhost）的浏览器；不提供降级到其他设备的方案。
- 模型首次加载约 1~3 秒（本地资源），低端机特征提取可能更慢；界面会显示加载状态，超时 30 秒可重试。
- 用户更换外观（眼镜、胡须、大幅妆容）或光线过暗时可能比对失败，建议重新录入。
- 模板与账号绑定，不跨账号复用；不提供管理员代录，避免代替他人授权。
- 车间共用终端建议保留密码登录作为兜底，并在制度上要求“人走锁定/退出”。
