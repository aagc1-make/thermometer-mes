## 一、人脸识别登入（约 4 分钟）

### 1.1 录入人脸（每人一次）

1. 用 `admin / admin123` + 验证码登录。
2. 右上角头像 → **个人中心** → 页签 **人脸登录**。
3. 状态显示“尚未录入人脸” → 点 **录入人脸**。
4. 弹窗中：输入**当前登录密码** → 勾选“我已阅读并同意上述说明，自愿录入人脸特征” → 点 **开始采集**。
5. 浏览器弹权限框时选“允许”。采集窗口会自动开始，窗口里只有 **取消 / 重新识别** 两个按钮，没有“开始”。
6. 按屏幕提示依次完成，顺序固定：
   - `请正对镜头，将一张脸放在取景框中央`
   - `请把脸缓缓转向左侧` → `请回正面向镜头`
   - `再请把脸转向右侧` → `请回正面向镜头`
   - `动作已完成，请正对镜头，保持不动`
   - `正在采集特征 1/3 … 3/3`
   - `识别成功`
7. 关闭窗口，个人中心显示 **已录入人脸**、样本帧数与模板数。

### 1.2 人脸登录

1. 右上角 → **退出登录**。
2. 登录页顶部三个页签：**密码登录 / 验证码登录 / 人脸登录** → 点 **人脸登录**。
3. 只输账号 `admin`（不输密码）→ 点 **开始人脸识别**。
4. 重复 1.1 的动作（左转 → 右转 → 采集 3 帧）。
5. 成功后直接进首页，菜单与权限和密码登录完全一致。

### 1.3 更新与管理

| 想演示什么 | 在哪操作 | 应看到 |
| --- | --- | --- |
| 更新人脸 | 个人中心 → **更新人脸** | 重新采集后覆盖主模板 |
| 补充侧脸/戴眼镜场景 | 个人中心 → **追加角度**（最多 3 个） | 模板数增加，比对取最近角度 |
| 解绑 | 个人中心 → **解绑人脸** → 输密码 | 模板立即删除，人脸登录失效 |
| 管理员停用/重置 | 用户管理 → 更多 → **人脸登录管理**；或 系统管理 → **人脸管理** | 可停用、重置某账号；旧算法模板标“需重录” |
| 失败限流 | 连续失败 5 次 | 10 分钟内拒绝人脸登录，**密码仍可登录** |

### 1.4 隐私边界（讲解 + 现场佐证）

讲解词：

> “检测、活体、128 维特征提取全在浏览器里完成；服务端只收到一串数字，模板用 AES-256-GCM 加密保存，密钥在部署环境里，数据库里看不到照片。录入和解绑都要再输一次密码，防止会话被盗后改绑。”

现场佐证：按 F12 → Network → 完成后点 `/faceLogin` 请求 → 请求体只有 `{username, descriptor}`，**没有图片或视频**。

### 1.5 出错怎么办

| 现象 | 处理 |
| --- | --- |
| “人脸录入暂不可用” | 后端没带 `MES_FACE_TEMPLATE_KEY`，按演示手册附录 A 重启后端 |
| “摄像头只能在 HTTPS 或 localhost 下使用” | 用 `http://localhost:8095` 访问，别用 IP |
| 一直停在“请正对镜头” | 光线太暗、脸太小或戴帽子；靠近镜头并补光 |
| 比对总失败 | 个人中心“更新人脸”重录；或追加角度 |

## 二、RAG 私有知识库与智能对话（约 5 分钟）

### 2.1 知识库操作

入口：智能助手 → **知识库管理**，顶部选 `MES Demo Library`。

1. **上传**：点“上传文档”，选文件（支持 `txt / csv / docx / xlsx / pdf`，单文件 ≤ 50 MB），填名称、分类、版本号，勾选是否“纳入知识图谱”，确认。
   - 分类只能选：检验规范 / BOM 说明 / 工艺说明 / 操作手册 / 其他。
2. **看状态流转**：列表依次为 解析（`parseStatus`）→ 向量化（`embedStatus`）→ 就绪；建图单独一列（`graphStatus`）。
3. **行内操作**：预览 / 下载原件 / 重试（解析失败）/ 重试建图（建图失败）/ **上传新版** / 删除。
   - “上传新版”是给同一文档加新版本，新版本生效、旧版本保留在版本列表里；删除会删掉该文档全部版本。
4. **部门隔离**：库绑定部门，接口会拒绝跨部门查询（提示“只能查看当前账号所属部门的知识库”），不同部门互相看不到资料。

**现场加分动作**：上传一份 docx 后立刻提问一个只有该文档才有的细节 → 能命中，说明向量化与检索是实时的，不是预先处理好的。

### 2.2 文档问答

1. 回 **智能问答**，模式选 **仅文档 RAG**。
2. 问：`红外传感器模块来料检验有哪些要求？`
3. 点气泡上方 `N 步` 展开轨迹，应含：

```
Dify · 问题改写（分支 文档）→ 向量与关键词检索（命中 4 个片段）
→ Dify · 文档检索 → 证据排序 → 回答生成 → 引用整理 → 完成回执
→ Dify 编排 · 运行 <编号> · 分支 文档
```

4. 点引用 → 打开原文并定位段落/页码。

讲解点：回答是流式逐字生成的；引用来自授权部门库；排序策略写在轨迹里（“关键词与向量融合排序”）。

### 2.3 大模型接入状态

徽标悬停或看 `/mes/ai/status`：

- `localModel: online` → 本机 Ollama `qwen2.5:7b-instruct`；
- `externalApi` → 配了 DeepSeek / GLM 密钥为 `configured`，未配为 `not_configured`；
- 生成顺序：本地模型 → 已授权外部 API → 仅检索。

### 2.4 Dify 工作流（加分项）

1. 打开 <http://127.0.0.1:8082>，登录 `admin@mes.local / MesDify2026!`，进「MES 智能问答编排」画布，指出 14 个节点：

```
领取本轮任务 → 问题改写确认 → 选择检索分支 →（文档 / 图谱 / 业务 / 混合两路）
→ 汇集阶段凭证 → 证据排序 → 回答生成 → 引用整理 → 完成回执 → 返回执行回执
```

2. 点左侧 **日志与标注**，按时间找到刚才那一轮（状态成功），与 MES 轨迹末条运行编号对照。
3. 点任一 HTTP 节点 → **数据处理**：请求体只有 `POST /mes/ai/dify/callback … {"stage":"…","ticket":"…"}`。
4. 收尾话术：

> “Dify 只做编排和分支判断；问题原文、文档片段、业务数据都在 MES，这就是私有化与数据边界。”

### 2.5 出错怎么办

| 现象 | 处理 |
| --- | --- |
| 文档题没有引用 | 文档是否“就绪”；换含文档关键词的问法 |
| 回答是原文片段 | 本地模型没起或超时；启动 `ollama serve` 后重问 |
| 轨迹没有 Dify 条目 | 徽标是否在线；`cd E:\dify\docker; docker compose up -d` 后重问 |
| 上传报“请选择有效的文档分类” | 分类只能选那五个 |
| 上传报超过 50 MB | 换小文件或拆分 |

## 三、GraphRAG 与知识图谱可视化（约 4 分钟）

### 3.1 建图（文档 → 图数据库）

1. 知识库管理 → 上传文档时勾选 **纳入知识图谱**。
   - 注意：开关只在**新建文档**时生效；给已有文档“上传新版”不会自动建图。
2. 列表看 `graphStatus`：`running → completed`；失败点 **重试建图**。
3. 抽取的实体类型：`Document / Item / Product / Process / InspectionItem / Defect`；关系类型：`USED_IN / HAS_PROCESS / CHECKED_BY / REQUIRES / MAY_CAUSE`。

### 3.2 图谱可视化

入口：智能助手 → **知识图谱**。

| 操作 | 应看到 |
| --- | --- |
| 搜索“红外传感器模块”或 `TG-EL-002` | 命中实体并高亮 |
| 实体类型筛选（Item / Product / Process…） | 只保留对应类型 |
| 关系类型筛选（如 `USED_IN`） | 只显示该关系 |
| 邻居跳数 1 / 2 | 展开一层或两层邻域 |
| 点节点 | 右侧面板出现实体详情、关联关系与**来源分块** |
| 聚焦 / 取消聚焦 | 以该实体为中心的局部子图 |

讲解：*“图数据在 Neo4j，前端通过 MES 的图谱接口取子图；每条关系都带来源分块，能点回原文。”*

### 3.3 GraphRAG 问答与对比

1. 智能问答 → 模式切 **图谱 GraphRAG**。
2. 问：`红外传感器模块与哪些检验项目有关？`
3. 轨迹应为：`图谱检索 · 关联 13 个实体、17 条关系 → 向量与关键词检索（命中 4 个片段）→ 证据排序（图谱关系与文档证据合并排序）→ …`，回答带引用编号。
4. 同一问题切回 **仅文档 RAG** 再问一次，对比“分支 文档”与“分支 图谱”的依据差异。

融合说明：图谱分支会把实体关系三元组拼进生成提示词（“实体关系及其文档引用”），与文档片段一起交给模型——这就是 RAG + GraphRAG 的提示词融合。

### 3.4 混合问答（可选）

模式选 **自动路由**，问：`检验规范怎样要求抽检？工单 MO202610270001 的过程检验结果如何？`

一条气泡里同时出现引用与业务表格；轨迹里 `混合问答·文档检索` 与 `混合问答·业务查询` 在**同一个运行编号**下。

### 3.5 出错怎么办

| 现象 | 处理 |
| --- | --- |
| 图谱页是空的 | Neo4j 没起；或 `mes.ai.graph.url` 写成 `bolt://`（必须是 `http://127.0.0.1:7474`） |
| 图谱题只给文档引用 | 模式没切到 GraphRAG，或问题里没有库中存在的实体名 |
| 上传后一直没建图 | 是否在新建文档时勾选；失败可点“重试建图” |

## 四、问答评测（1 分钟）

1. 智能助手 → **问答评测**（仅 admin 可见）。
2. 范围选 `MES Demo Library` → 点 **运行评测**（约 0.5 秒）。
3. 四张卡片应全部 100%：

| 指标 | 结果 |
| --- | --- |
| Recall@5 | 2/2 |
| 数值正确率 | 3/3 |
| 引用覆盖率 | 8/8 |
| 三元组抽检准确率 | 6/6 |

4. 点任一卡片 → 点一条样例 → 右侧对照 **核对依据 / 实际结果**；右上可 **下载报告**。

讲解：显示 `—` 是**标注缺失被跳过，不是 0 分**；评测不经过 Dify，评的是检索与数据口径。
