# 产品需求文档 · 工单缺料分析与调拨草稿

| 项目 | 内容 |
| --- | --- |
| 版本 | V1.1 评审稿，2026 年 11 月 22 日 |
| 适用系统 | 红外测温枪 MES，PC 端工单管理、首页工单流水线、转移调拨 |
| 主要用户 | 计划员核对缺口，具备调拨新增权限的人员建草稿，仓管员办理上架和执行 |
| 交付目标 | 从一张工单出发，用户能核对每种外购料缺多少、从哪个批次补、还需采购跟进多少，并打开确认生成的调拨单。 |

## 使用场景

计划员准备下达一批红外测温枪。以显示屏为例，工单物料清单需要 100 片，已领 30 片，原料仓还有 50 片。原先看板能提示缺料，查其他仓库、选批次和录入调拨明细还要跨页面操作。新面板显示缺口 20 片。假设其他原料仓只有 12 片符合条件，计划员可勾选这 12 片生成调拨草稿，剩余 8 片显示“待采购跟进”。数字为验收示例。

计划员负责核对短缺物料和补料方案，有权建单的人员确认本次调拨明细，仓管员在转移调拨页面完成实物调拨。三方以工单号和关联调拨单号交接。若需要采购跟进，计划员可从面板取得物料编码、单位和仍需补足的数量，按现行采购流程处理。

## 用户流程与交付范围

| 环节 | 用户操作 | 页面反馈及业务结果 |
| --- | --- | --- |
| 进入 | 在已有工单详情的“物料需求”或首页工单流水线点击“分析缺料” | 自动使用当前工单 ID。面板展示工单号、每种物料的单位、需求、已领、原料仓现存和缺口。未保存的新工单不可发起分析。 |
| 核对 | 查看当前不足的物料及候选批次 | 每行显示来源仓、库区、库位、批次、可调量和建议量。完整建议未覆盖的数量按物料列入“待采购跟进”。 |
| 解读 | 可选“请 AI 解读缺料依据”，确认发送范围 | 已配置模型解读前 12 种缺料的数量和建议。用户可继续查看表格、勾选和建草稿。 |
| 确认 | 勾选 1 至 500 条来源明细，核对本次拟调数量后点击“确认生成调拨草稿” | 后端重新核对工单及所选建议，一次创建一张内部转移单及勾选的明细。成功后显示单号、状态和查看入口。 |
| 跟进 | 打开“关联调拨单”里的单号 | 沿用转移调拨页面办理提交、上架和执行。草稿标明目标原料仓 WH-RAW，仓管员在上架时选择该仓的目标库位。 |

### 面板上的数量

面板按物料显示数量和单位。不同物料的数量分别呈现，确认按钮只汇总选中的调拨明细行数。

| 字段 | 计算口径 | 示例（片） |
| --- | --- | --- |
| 当前缺口 | 工单需求减已领量，再减原料仓现存，最低为零。 | 100 − 30 − 50 = 20 |
| 建议调拨量 | 当前分析为该物料分配的全部合格来源批次数量之和。 | 两个批次分别可补 7 和 5，共 12 |
| 待采购跟进 | 当前缺口减建议调拨量，表示全部建议都采纳时仍缺的数量。 | 20 − 12 = 8 |
| 本次拟调数量 | 已勾选的批次建议量，随勾选更新。数量来自建议行。 | 只勾选第一批次，拟调 7 |
| 按本次选择预计剩余 | 当前缺口减本次拟调数量，包含未选建议量和待采购跟进量。 | 20 − 7 = 13，其中 5 可从未选批次调入，8 待采购跟进 |

候选通过勾选加入本次草稿，初始无勾选。用户可按物料核对拟调数量和预计剩余。建成草稿后，当前缺口仍按实物库存和实领量显示，同时展示在途调拨单及状态。仓管执行后重新分析，才把实际调入量计入原料仓现存。

### AI 解读

用户确认后，模型收到本次分析中前 12 种缺料的物料名称、单位、需求、已领、原料仓现存、缺口、建议调拨总量和待采购跟进量。超过 12 种时，面板说明解读覆盖范围，完整结果仍在表内。模型解释数量和可调拨方案。数量、批次和确认资格以服务端计算结果为准，建单由具备权限的用户确认触发。

## 数量与来源规则

1. 按工单 BOM 中用量为正的外购物料汇总。工单 BOM 数量已包含计划产量。同一物料的重复行合并，各物料沿用自身的基本单位。
2. 已领量取归属本工单、状态为 FINISHED 的领料单行。原料仓现存沿用看板对 WH-RAW 非冻结正库存的口径。缺口取“需求量减已领量减原料仓现存量”与零的较大值。
3. 候选来源取 WH-RAW 以外的实体 RAW 类型仓库，排除冻结的库存、仓库、库区和库位，要求库位已启用、批次归属正确且在有效期内。批次质量沿用现有领料规则，接受 OK 或历史空值。已绑定工单的来源库存另作专用。
4. 来源行的可调量等于账面量扣除该库存行上未完成、未撤销的调拨单数量。按入库时间及库存记录 ID 依次分配，每笔建议取“可调量”和“该物料剩余缺口”中较小的值。
5. 有建单权限的操作人选定来源生成草稿后，本工单显示关联单号。存在进行中的关联单时先处理该单。完成或撤销后，按当时库存重新分析。采购跟进数量用作人工处理提示。正式请购、供应商下单和交期承诺留待采购系统接入。
6. 确认接口接收确认标识、已展示的库存 ID 和建议版本。服务端发现任意一行失效时整单拒绝，要求用户刷新后重新选择。库存流水由既有调拨执行步骤生成。

## 调拨单状态和交接

| 状态 | 业务动作 | 工单缺料面板 |
| --- | --- | --- |
| 草稿（`PREPARE`） | 服务端保存内部转移单和所选明细，写入来源工单和目标仓。库存账面量保持原值，草稿明细纳入后续可调量计算。 | 显示单号和状态，引导有权限的用户打开现有草稿。 |
| 待上架（`UNSTOCK`） | 有权人员提交单据，仓管员在 WH-RAW 选定目标库位，核对每行上架数量。 | 显示在途单据，建单入口停用。 |
| 待执行（`UNEXECUTE`） | 上架明细的数量与单据行数量一致后，仓管员提交到待执行状态。 | 显示在途单据，建单入口停用。 |
| 已完成（`FINISHED`） | 执行既有转移库存流程，生成来源扣减和目标增加的库存流水。 | 保留关联单号，刷新后按实物库存重算缺口。 |
| 已撤销（`CANCELED`） | 有权人员在执行前撤销，保留单号和操作记录，释放该单对后续建议量的占用。 | 保留关联单号，刷新后可按剩余缺口发起下一张。 |

## 异常处理

| 场景 | 用户看到的结果和下一步 |
| --- | --- |
| 分析加载失败或工单不存在 | 清空旧工单结果及勾选项。加载失败可重试，工单不存在则返回工单列表核对。 |
| 缺口为零、没有可核算外购 BOM、或有缺口但无合格来源 | 分别显示“外购料已齐套”“请核对工单物料”和“待采购跟进”。三种情形都停用建单操作。 |
| 来源批次、可调量或选中行的缺料依据发生变化 | 提示刷新并重新选择。刷新前停用确认，服务端保留建单前的状态。 |
| 同工单已有在途调拨 | 显示已有单据及状态。操作人可查看或交接，待该单完成或撤销后继续。 |
| 确认超时或连接断开 | 提示结果待核对。刷新的第一步是检查关联单据。已落库时显示原单，未落库时按新分析重新选择。客户端重试同一组请求参数时由服务端返回原单。 |
| 已收到建单成功响应，随后刷新失败 | 保留已返回的单号和状态，允许重试刷新。具备查询权限时可通过单号打开单据。 |
| 模型超时或服务不可用 | 解读区域显示失败提示，缺料表和建单功能继续可用。 |
| 刷新、关闭面板或切换到别的工单 | 清除过时勾选和解读。旧请求返回时，只能更新发起该请求且仍有效的工单面板。 |

## 权限、数据与接口

| 操作 | 权限或约束 |
| --- | --- |
| 分析 | 同时具备工单查询、库存列表、领料单列表、调拨单列表权限。由服务端核验，前端按同一权限集合展示入口。 |
| 确认 | 在分析权限基础上具备调拨新增权限。完工、撤销工单只允许查看。确认期间停用重复提交。 |
| 跳转 | 调拨查询权限控制打开已有单据。 |
| 关联与追溯 | 复用调拨头、行、编码规则、创建人和操作日志。头表 attr1 保存带前缀的来源工单 ID，attr2 保存本次确认标识及选择摘要。 |
| 幂等与事务 | 确认按工单串行化，再按 ID 锁定所选来源库存。同工单用相同标识、相同库存 ID 和建议版本重试时返回原单。相同标识更换选中项时要求重新分析。明细失败回滚整张单。 |

| 接口 | 输入 | 结果 |
| --- | --- | --- |
| `GET /mes/pro/workorder/{id}/shortage` | 工单 ID | 工单号、关闭状态、物料清单、来源建议、关联调拨单、本次确认标识 |
| `POST /mes/pro/workorder/{id}/shortage/draft` | `requestId` 和 `lines`，每行包含 `stockId` 与 `version` | 已持久化的调拨单 ID、单号、状态，或要求刷新核对的业务原因 |
| `POST /mes/ai/analysis` | 当前缺料的结构化事实、解读问题 | 模型说明文本 |

## 验收场景

| 编号 | 场景与操作 | 可核对结果 |
| --- | --- | --- |
| AC-01 | 从工单详情和首页分别打开同一测试工单。需求 100、已领 30、原料仓现存 50，来源共 12。 | 两个入口显示相同工单、缺口 20、建议调拨 12、待采购跟进 8。 |
| AC-02 | 分别打开外购料已齐套、只有自制件、BOM 为空和有缺口无合格来源的工单。 | 齐套显示已覆盖，只有自制件或 BOM 为空时提示核对外购 BOM，有缺口无来源时待采购跟进量等于缺口。四种情形均无法提交空单。 |
| AC-03 | 缺口为 20，两个合格批次建议量是 7 和 5，只勾选第一批次。 | 确认前显示本次拟调 7、预计剩余 13、待采购跟进仍为 8。生成一张 `PREPARE` 单，明细只有选中批次的 7 片。草稿阶段库存和流水保持原值。 |
| AC-04 | 准备过期批次、冻结库位、虚拟仓、已绑定工单的专用库存，以及账面量 12 且被在途调拨占用 5 的合格库存。 | 前四类来源被排除。最后一行可调量为 7，建议量最多为 7。 |
| AC-05 | 勾选后改变任意已选批次的可调量，再提交原版本。模拟写入某一明细失败。 | 版本失效时要求刷新并重选。两种失败均未留下新调拨单头或明细。 |
| AC-06 | 同一工单两个账号同时确认，再用成功请求的原参数重试。另用相同标识换一组明细确认。 | 只生成一张在途单，成功请求重试返回原单，改选请求要求重新核对。两个不同工单争用同一来源且余额不足时，后确认者须重新分析。 |
| AC-07 | 生成草稿时模拟成功响应丢失。另模拟建单成功后刷新超时。 | 前一种可从刷新后的关联单据找到原单，原参数重试返回同一单号。后一种仍能看到已返回的单号。 |
| AC-08 | 分别使用具备分析权限的只读账号、缺少分析权限的账号及完工工单。 | 只读账号可看结果，直接提交确认请求仍被拒绝。缺少分析权限时前端和服务端都拒绝分析。完工工单可查历史，无法建新单。 |
| AC-09 | 解读 13 种缺料，并模拟模型超时。关闭面板或切换工单后再让旧请求返回。 | 确认提示和实际模型输入均限定在前 12 种。完整缺料表仍可使用，超时期间可建草稿，迟到响应不覆盖当前工单。 |
| AC-10 | 对 7 片草稿走完提交、在 WH-RAW 上架和执行，随后重新分析。另验证撤销路径。 | 在没有其他库存变动的前提下，执行后来源减 7、原料仓增 7，缺口从 20 降至 13。选择非 WH-RAW 库位时拒绝提交上架。执行前撤销保留单号及状态，重新分析时该单的占用解除。 |

## 评审与上线验收

发布时同步更新 Java 后端和 Vue 前端。本版复用既有调拨表字段。现场选一张可复现缺口的测试工单，使用有建单权限、只读和仓管三类账号，记录初始库存、分析结果、调拨单号、执行前后流水以及刷新的缺口。

评审稿新增了按勾选预览数量、刷新失败后保留单号、目标仓库位校验及草稿撤销保留单号的验收口径。现有上架流程的数量校验和撤销入口需按上述验收场景核对，其中现有转移页面在草稿状态未提供撤销入口。全流程是否通过，以现场验收记录为准。
