# 知识库演示文档包

用于演示「智能助手 → 知识库 / 仅文档 RAG / 图谱 GraphRAG / 数据问答」四块功能。
所有物料、工序、检验项编码都取自 `sql/thermometer_init.sql` 的演示数据，
**所以文档里的编码可以直接在系统里查到真实记录**，混合问题（规范 + 实时库存）才问得通。

重新生成：`python scripts/gen-demo-kb-docs.py`

| `03_TG-FG-001整机装配与校准工艺说明_V1.1.docx` | docx | 生产部库 | 工序/设备/参数、过程检验 |

## 二、文件之间的“钩子”（这是设计出来的）

- **编码一致**：`TG-FG-001` 整机、`TG-EL-002` 传感器、`TG-SF-001` 电控预装件、`TG-OP70` 温度校准、
  `TG-OP80` 出货检验——四份文档用同一套编码，图谱才能把跨文档的实体连起来。
- **互相引用**：整机检验规范引用 `Q/TC-GY-001`（工艺）和 `Q/TC-JY-002`（来料），
  来料指导书回指 `TG-SF-001`，BOM 说明写明“传感器唯一用于电控预装件”。顺着引用问下去能演示多跳。
- **可拒答**：文档里**没有**写客户投诉时限、也不写具体库存数量（第 6 章明确“以系统实时为准”）。
  这两类问题正好用来演示“拒答”和“转数据问答”。
- **可做版本差异**：V1.2 把功能 AQL 从 `1.0` 收紧到 `0.65`，并新增 `5.6 自动关机` 检验项；
  旧版没有这两处。上传新版后问“功能 AQL 是多少”，回答应引用 V1.2 并给 0.65。

> 说明：文档里的抽样表是按 GB/T 2828.1 的常用批量段**简化和示意**的，用于演示检索与判定逻辑，
> 不作为标准原文引用。答辩时若被追问，如实说明“示意表，真实判定以标准表为准”。

## 三、演示脚本（按此顺序最顺）

### 1. 上传（知识库 → 上传文档）

先传 `01_…V1.0_旧版.docx`，标题填「红外测温枪整机检验规范」，分类「检验规范」，版本 `V1.0`，
打开「纳入知识图谱」。等「解析 / 向量 / 图谱 / 就绪」四段全绿。

### 2. 只读文档问答（模式：仅文档 RAG）

| 提问 | 期望回答要点 |
| --- | --- |
| 红外传感器来料检验有哪些要求？ | 抽 5 件、AQL 0.65、I2C 0x5A、黑体炉 37.0℃ 偏差 ≤±0.2℃、开封 7 天（引用 02 文档 2/3/5 章） |
| 整机出货检验的外观和功能 AQL 分别是多少？ | 外观 1.0、功能 **1.0**（因为此时只有旧版） |
| 温度校准要测哪几个温度点？ | 35.0 / 37.0 / 42.0℃，每点 3 次取均值，偏差 ≤±0.2℃（引用 03 文档 3.4） |

点回答里的 `[1]`：右侧抽屉应给出原文片段、文档名与版本——这是“可核对”。

### 3. 版本更新（同一文档上传新版）

在知识库对同一份文档点「上传新版」，选 `01_…V1.2.docx`，版本填 `V1.2`。
索引完成后重复上面的问题：

- 期望：功能 AQL 变成 **0.65**，引用指向 V1.2，页面/条款为 `4.2`。
- 话术：新版索引成功前旧版一直可用，不会出现“更新到一半搜不到”。

### 4. 拒答（证明不编）

| 提问 | 期望 |
| --- | --- |
| 客户投诉多少小时内必须响应？ | 明确说资料未收录/证据不足，不编时限 |
| TG-EL-002 现在还有多少库存？ | 提示这是实时数据，应走「数据问答」（切模式再问一次，得出真实数量） |

### 5. 图谱（模式：图谱 GraphRAG）

| 提问 | 期望 |
| --- | --- |
| 红外传感器模块用于哪个产品？ | 回答给出 `TG-EL-002 → TG-SF-001 → TG-FG-001` 的链路，下方出现「图谱子图 · N 个实体」 |
| 温度校准是哪道工序？用什么设备？ | `TG-OP70`，黑体炉；子图里能看到工序与设备节点 |
| 哪些工序属于过程检验？ | OP20、OP40、OP70、OP80（依据 03 文档工艺路线表） |

点「图谱子图」按钮 → 右侧抽屉看节点与关系；再到「知识图谱」页搜 `TG-EL-002`，
切 2 跳、点「展开邻居」，演示可视化本身。

### 6. 混合问题（模式：自动路由）

> `TG-EL-002 的来料检验要求和存储条件是什么，现在还有多少库存？`

期望：一轮里同时给出文档引用（抽样 5 件、15–30℃、开封 7 天）+ 库存表格 + 「数据来源」。
这一问是整场演示的高光——**三路统一路由**一次讲完。

### 7. 用文档“钓鱼”的加分问法

| 提问 | 为什么好 |
| --- | --- |
| 安全库存怎么算？现在哪些物料低于安全库存？ | 规范给公式、系统给名单，正好对撞 |
| 如果 TG-EL-002 低于安全库存，按办法要通知谁？ | 文档说“同步质量部”，考的是跨条款组合 |
| 我这个工单 OP70 校准超差三台了怎么办？ | 工艺说明第 5 章有明确处置，能命中“异常处理”表 |

## 四、几个坑

1. **别只传 PDF 扫描件**：无文字层会报“未检测到文本”，本环境不做 OCR。
2. **编码写错就查不到**：`TG-EL-002` 有连字符，写成 `TGEL002` 规则不认，文档检索也会跑偏。
3. **同一文档的新版要在原文档上「上传新版」**，不要新建一条同名文档，否则会变成两份互相竞争的资料。
4. **图谱要等**：导入后建图是异步的（约 2.5 秒轮询一次），文档多时留 1–2 分钟再演示。
5. **别在文档里写实时数字**（库存、在制数），否则 RAG 会引用过期数字，和「数据问答」当场打架——
   这也是第 06 份文档特意写“不载明数量”的原因。
